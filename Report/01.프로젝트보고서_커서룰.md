# MagicSquare 프로젝트 보고서

작성일: 2026-05-18

## 1. 프로젝트 개요

MagicSquare는 Python 기반의 매직 스퀘어 도메인 프로젝트입니다. 현재 프로젝트는
Python 3.10 이상을 기준으로 하며, ECB(Entity-Control-Boundary) 아키텍처와
TDD(Test-Driven Development) 흐름을 개발 원칙으로 채택하고 있습니다.

현재 구현은 사용자 도메인 엔티티인 `User`를 중심으로 시작되어 있으며, 도메인
규칙은 `entity` 계층에 위치합니다. 테스트는 `pytest`를 기준으로 작성되어 있고,
`tests` 디렉터리에서 대상 계층 구조를 반영합니다.

## 2. 현재 파일 구성

```text
MagicSquare_13/
  .cursorrules
  pyproject.toml
  entity/
    __init__.py
    user.py
  tests/
    entity/
      test_user.py
  Report/
    project_report.md
```

## 3. 개발 규칙 요약

`.cursorrules`에는 프로젝트의 주요 개발 규칙이 정의되어 있습니다.

- Python 버전은 `3.10+`를 기준으로 합니다.
- 코드 스타일은 PEP8을 엄격히 따릅니다.
- 모든 함수 파라미터와 반환값에는 타입힌트를 작성해야 합니다.
- public 메서드는 Google 스타일 docstring을 작성해야 합니다.
- 최대 줄 길이는 Black 기준인 88자를 따릅니다.
- 기능 구현은 TDD의 red, green, refactor 단계를 기준으로 진행합니다.

## 4. ECB 아키텍처 적용 현황

프로젝트는 ECB 패턴을 기준으로 계층을 분리합니다.

- `entity`: 도메인 데이터와 도메인 규칙을 담당합니다.
- `control`: use case와 비즈니스 흐름을 담당할 예정입니다.
- `boundary`: CLI, API, UI 등 외부 입출력을 담당할 예정입니다.

현재 구현된 주요 계층은 `entity`입니다. `User` 클래스는 외부 입출력이나
use case 흐름에 의존하지 않고 사용자 식별자, 표시 이름, 이메일에 대한 도메인
규칙을 자체적으로 검증합니다. 이는 `.cursorrules`의 의존성 방향인
`boundary -> control -> entity` 규칙과 충돌하지 않습니다.

## 5. User 엔티티 구현 현황

`entity/user.py`에는 `User` 엔티티가 구현되어 있습니다.

주요 특징은 다음과 같습니다.

- `dataclass` 기반의 불변 엔티티입니다.
- `slots=True`를 사용해 불필요한 동적 속성 생성을 방지합니다.
- 동일성 비교는 `user_id` 기준으로 수행합니다.
- `user_id`, `display_name`, `email` 값은 생성 시 정규화 및 검증됩니다.
- 표시 이름과 이메일 변경은 기존 인스턴스를 수정하지 않고 새 인스턴스를 반환합니다.

현재 정의된 주요 도메인 규칙은 다음과 같습니다.

- `user_id`는 공백 제거 후 비어 있을 수 없습니다.
- `user_id`는 최대 64자입니다.
- `display_name`은 공백 제거 후 비어 있을 수 없습니다.
- `display_name`은 최대 120자입니다.
- `email`은 선택값이며, 빈 문자열은 `None`으로 정규화됩니다.
- `email`은 최대 254자이며 `@` 문자를 포함해야 합니다.

## 6. 테스트 현황

`tests/entity/test_user.py`에는 `User` 엔티티에 대한 단위 테스트가 작성되어
있습니다. 테스트는 AAA(Arrange-Act-Assert) 패턴을 따르며, `test_` 접두사
네이밍 규칙을 지킵니다.

현재 테스트가 검증하는 내용은 다음과 같습니다.

- 필수 필드만으로 사용자를 생성할 수 있습니다.
- `user_id`, `display_name`, `email`의 앞뒤 공백이 정규화됩니다.
- 빈 이메일 문자열은 `None`으로 변환됩니다.
- 동일성은 `user_id` 기준으로 판단됩니다.
- `User`가 아닌 객체와의 비교는 `NotImplemented`를 반환합니다.
- `User` 엔티티는 생성 후 직접 변경할 수 없습니다.
- 표시 이름과 이메일 변경 메서드는 새 인스턴스를 반환합니다.
- 잘못된 필드 값은 `ValueError`를 발생시킵니다.

## 7. 검증 결과

현재 환경에서 수행한 검증 결과는 다음과 같습니다.

- `python -m compileall entity tests`: 성공
- IDE 진단 기준 `entity/user.py`, `tests/entity/test_user.py`: 오류 없음
- `python -m pytest`: 실패

`pytest` 실패 원인은 테스트 실패가 아니라 현재 Python 환경에 `pytest` 패키지가
설치되어 있지 않기 때문입니다. `pyproject.toml`에는 개발 의존성으로
`pytest>=8.0`이 정의되어 있습니다.

## 8. 향후 작업 제안

다음 단계에서는 MagicSquare 도메인의 핵심 엔티티를 추가하는 것이 좋습니다.

- `entity/magic_square.py`에 매직 스퀘어 값과 규칙을 정의합니다.
- `tests/entity/test_magic_square.py`에 매직 스퀘어 생성과 검증 테스트를 작성합니다.
- 이후 `control` 계층에 매직 스퀘어 생성 use case를 추가합니다.
- 마지막으로 `boundary` 계층에 CLI 또는 API 입출력을 연결합니다.

이 순서를 따르면 ECB 의존성 방향을 유지하면서 TDD 흐름으로 기능을 확장할 수
있습니다.
